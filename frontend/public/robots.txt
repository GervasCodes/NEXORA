# Public, unauthenticated pages (home, /products, /products/:slug,
# /services, /services/:slug, /stores/:slug, /departments/:slug,
# /guides, /group-buys, /live-selling, /legal/:slug, /status) are left
# crawlable by default below — there's no Disallow for them.
#
# /login, /register and /forgot-password are also left crawlable on
# purpose: they carry <PageMeta noIndex />, and Google can only honor a
# noindex it is allowed to fetch. Same reasoning as /group-buys/:id below.
#
# Everything Disallow'd here is a route that only ever renders behind
# RequireAuth/RequireBuyer/RequireSeller/RequireDeliveryAgent/RequireAdmin
# (see frontend/src/App.jsx) — a crawler can't authenticate, so there's
# nothing indexable behind these paths anyway; blocking them just saves
# crawl budget. This list mirrors the same route groups already marked
# `noIndex` in the pages' own <PageMeta noIndex /> usage.
#
# /search (internal search results) is likewise left crawlable: it is
# <PageMeta noIndexFollow />, so Google must be able to fetch it to read
# that tag. Auth pages are therefore NOT Disallow'd here.
#
# One route is marked `noIndex` but is NOT behind an auth gate —
# /group-buys/:id (see GroupBuyDetail.jsx). It is deliberately left OUT
# of Disallow below: unlike the auth-gated routes, a crawler CAN reach it, so
# blocking the crawl would stop Google from ever seeing the noindex
# meta tag on the page itself — the well-known robots.txt-vs-meta-
# noindex conflict. Leaving it crawlable lets the per-page noindex
# tag do its job as intended.
